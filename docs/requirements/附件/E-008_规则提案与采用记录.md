## S组提案原表

| 编号 | AI建议 | 需要表达清楚的边界 |
|---|---|---|
| S1 | 用户从本人预约发起座位被占求助，也可提交其他服务投诉；管理员核实、处理并反馈，用户可看本人处理进度 | 报告关联座位、预约及描述，不要求用户自行知道对方身份，也不强制上传照片；管理员能处理全校纳入管理范围 |
| S2 | 自习空间开放时段内，座位被占求助以15分钟内受理为管理目标；超时标记并提示管理员。非开放时段从下次开放时刻计算 | 受理表示有人接手核查，不等于保证15分钟到场或解决；其他普通服务投诉以24小时内首次反馈为候选目标，待统一质量表核对 |
| S3 | 未签到超时和开始后未签到主动放弃由系统自动登记；拒不配合纠正占座由管理员核实身份和事实后登记 | 提醒记录不计违规。同一预约的同类未签到违约只记一次；系统故障或管理原因取消不能归成用户违约。其他违规类型不擅自扩展 |
| S4 | 一个处罚周期内，30天累计3次有效违规，暂停预约7天；到期自动恢复 | 次数和期限均为AI建议。已撤销违规不计；同一违规不重复触发处罚，恢复后从新发生违规重新累计，旧记录仍留存查询 |
| S5 | 暂停预约期间禁止提交新预约；已有未签到预约由系统取消并通知，不新增违约；已经签到的预约可使用至原结束时间 | 不强行提前结束本次正在使用的预约；取消已开始但未签到预约也不额外计未签到违约，记录管理取消原因 |
| S6 | 用户可在违规通知后7天内申诉；管理员核查并反馈，成立则撤销违规、重算次数及限制 | 不直接删除原始记录；误判解除后已取消预约不自动恢复，以免占用他人后来取得的预约，可提示重新预约。未处理申诉不会自动撤销原限制 |
| S7 | 管理员可手动加入或解除黑名单，必须填写已核实的事实、理由、操作人和截止时间，保留操作记录 | 手动限制不能仅凭未核实投诉；普通提醒不作为直接加入依据。手动限制由管理员确认解除或到期结束；与自动限制分别保留来源 |
| S8 | 用户因座位被占或平台故障错过签到，可说明情况；管理员核实后撤销误记违约，必要时为仍有效且无冲突的预约补签 | 投诉提交本身不自动延长签到期限。已经释放且被他人预约的时段不强行恢复；补签、撤销和其他协助结果都要反馈并留记录 |

## DEC-12 本轮团队确认（2026-10-29）

由潘煜代表第11组转述共同讨论结论；未补造个人发言或会议工时。

| 事项 | 当前决定及影响 |
|---|---|
| 时长与额度 | 取消每天累计4小时及单次最长4小时限制；保留最短30分钟、开放、冲突和签到规则；覆盖历史R3中两类上限及原额度公式 |
| 并列排序 | 接受按开始时间、位置和编号稳定排序 |
| 限制期间新违规 | 计入恢复后的新周期，保留事件原发生时间；沿用回溯30天与旧处罚不重复使用 |
| 投诉确认 | 接受待受理撤回与异议继续核查；可留出确认时间后自动结案，DEC-13将确认期确定为本次反馈发出后7天 |

以上为团队项目规则确认，独立于RF-02—RF-07的使用者反馈。新规则及P0.4均待后续场景复验。

DEC-13补充：潘煜于2026-10-29确定投诉反馈确认期为7天；从本次处理反馈发出时刻计算7×24小时，期限内有异议转回处理中，届满仍无确认或异议才自动结案。
