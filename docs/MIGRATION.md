# Java / PostgreSQL 迁移说明

基于 [imicola/smart-study-room](https://github.com/imicola/smart-study-room)，起始提交 `e76a10d918451cd75057ee6b2d404db93c1f5aa4`，保留上游 MIT 许可证与作者归属。

## 当前实现

- 后端：Java 17、Spring Boot 2.7.18、Spring JDBC、PostgreSQL JDBC 42.7.14、Redis、JWT、BCrypt。
- 数据库：Docker `postgres:17-alpine`，宿主5433端口，独立持久化卷；开发库 `studyroom_java`，测试库 `studyroom_java_test`。
- 前端：保留上游 Vue 3 页面、2D / 3D 座位图、统计与管理页；移除智能助手组件、请求代码与入口。
- 工程：删除当前工作树中的 Go 后端，以 `backend/` 中的 Java 实现为唯一后端。原始实现仍可通过 Git 历史查看。
- 文档：原作者文档和旧脚本归档到 `docs/upstream/`。其中的报告、测试数字与设计图不代表本次 Java 实现。

最初曾参考用户旧 Java 项目接入 openGauss；随后依用户与教师要求改为 PostgreSQL。**当前代码、启动脚本与验证均以 PostgreSQL 为准，不依赖 openGauss JDBC JAR。**旧 openGauss 容器和原有业务库没有修改，也没有搬迁或删除其中数据。新 PostgreSQL 库初始化的是课程演示数据，不是校内真实数据。

## 一致性和接口

保留原前端 `/api` 路径、snake_case 字段、状态名和响应结构。Java record 入参显式标注字段名，并补充反序列化契约测试。日期返回 `YYYY-MM-DD`，时间戳与日期分别映射。

所有预约、状态流转和资源写事务先对 `booking_mutex` 固定行执行 `SELECT FOR UPDATE`，再校验座位/用户冲突并写入。失败时预约、相关流水与通知由同一事务回滚。选择串行化短写事务适应教学场景，不据此宣称达到上游 README 中的高并发性能。直接绕过服务写数据库会绕过业务校验。

Redis 用于限流和注销令牌撤销；账号禁用状态还会在每次请求时从数据库核查。使用独立3号库及键前缀，没有清空用户原 Redis 数据。

已实现校园账号维护/CSV导入/联系方式、教职工与学生统一权限、空间位置/真实容量/单座位维护，以及分段开放/日期例外/临时停用。S07关闭候补和属性偏好自动分配新增及递补，保留真实历史和本人退出旧等待；手动预约按D至D+2、分钟精度和最短30分钟统一校验。S08区分开始前取消与开始后未签到放弃、独立自动违规及截止释放，停止新增信用奖惩；S09接本人携当前座位码签到，S10以唯一usage_records记录签到和结束并退出暂离。存在有效预约的资源变更若有真实影响则拒绝，历史资源禁止直接删除；S13再实现影响预览、确认、管理取消和通知。

统计从usage_records读取签到到签退/结算事实，旧预约时间列只读溯源，未签到违约不算实际使用；分母和热力窗口读取统一开放安排，完整指标改造留S29。旧规则评分随S07退出新增，S11最早连续空档及同源图列表已接入，最长及所需时长方案待S12。智能助手接口、配置和会话表已移除。
