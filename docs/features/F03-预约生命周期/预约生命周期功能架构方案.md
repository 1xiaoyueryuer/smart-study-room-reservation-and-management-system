## S07 固定数据、接口与流程

1. 唯一Slot内部使用date及startMinute(0..1439)、endMinute(1..1440)；start<end，至少30分钟。新前端使用HH:mm；后端兼容HH:mm:00及纯零小数为同一整分钟，非零秒/纳秒拒绝。结束24:00/24:00:00及零小数同义，开始24拒绝。日期范围按Asia/Shanghai自然日D至D+2，起点>=服务端提交时刻。不设单次4/8小时或每日累计4小时上限，仍受合法连续开放、资格及冲突约束。
2. end=24:00只表示所选日右开结束边界，即date.atStartOfDay()+1440分钟；start不可24:00，22:00—次日02:00仍拒绝。D+2以24:00结束不等于允许选择D+3日期。时长和所有日期时间端点统一由Slot计算，不做v2实现。
3. PostgreSQL原TIME列保留。写入与比较用规范文本显式CAST(? AS TIME)，Store对Types.TIME优先取原文本，不能经过java.sql.Time/LocalTime把24归零。历史原值保持，不能将24改23:59或把真正00一概当24。BookingService写入/冲突/starts/ends/调度、ResourceService座位图查询、OpeningScheduleService包含/影响和Stats结算/热力端点共用同一转换。历史raw TIME读取端点保留原秒/小数并正常读取、结束，不把旧记录强塞进新预约整分钟校验；24零边界按次日处理，不重写旧值。此兼容为主agent技术决定，不新增人工逐项确认。
4. GET `/api/booking-policy`面向登录普通用户，返回server_now（带明确时区）、campus_today、dates、campus_zone、min_duration_minutes=30。创建使用同一政策及Clock；前端不自行推算校园自然日，当前时刻含秒时建议起点向上到下一分钟，不伪造提前10分钟。
5. 手动POST `/api/reservations`仍在booking_mutex事务内复查普通身份、有效资格、日期时长、空间/座位状态、S06开放和停用、座位/本人冲突。失败400/403/409保持原状态；资源/审计依赖故障明确未完成，不能返回假成功。
6. HTTP及service的旧POST `/api/reservations/auto`、POST `/api/waitlist`明确410说明退出新增；管理员仍不具普通预约权限，未登录仍401。关闭打分/偏好分配与候补新增，tick不再递补创建；不能仅隐藏UI留下可调用新增写路径。
7. 保留真实历史source(manual/auto/waitlist)、原候补记录及状态；历史查询仍可达，本人可退出旧waiting，终态重复/越权依旧拒绝。历史页不承诺即将递补，不把旧记录批量伪造成取消或过期。属性字段可展示，不保留属性偏好自动分配入口。
