## S01 迁移与审计基础

关联 P40、BR-23、QN-04/06；不变更已确认业务规则、预约状态或权限矩阵。旧代码以 schema.sql 重复建表，缺少升级历史；request.js 丢弃 HTTP 状态。采用 Flyway 10.20.1（core 与 PostgreSQL 模块同版本），由显式 Flyway Bean 在返回前核对并迁移 public schema；避免 Boot 2 旧属性绑定与新版API差异。参考官方 [Spring Boot 迁移说明](https://docs.spring.io/spring-boot/docs/2.7.x/reference/html/howto.html) 与 [Flyway baseline 语义](https://documentation.red-gate.com/flyway/reference/commands/baseline)。本机 PostgreSQL17.11 集成与启动回归已通过。

- V1 固化原 schema.sql 的表、列、约束、索引及 mutex 初值；删除旧自动建表脚本，sql.init.mode=never，Flyway 为唯一结构升级入口。
- 空库执行 V1、V2；已有迁移历史校验 checksum 并执行增量；clean-disabled=true。
- 无历史的非空库默认拒绝。停服务并备份后，操作人显式设置 `studyroom.migration.adopt-legacy=true`，程序在同库事务内建立临时参考 schema，对比 V1 关系、列、默认值、约束、索引及额外触发器；不吻合则诊断并拒绝，不写 baseline。参考 schema 始终回滚。核对通过才标记 baseline 1 并执行 V2。该开关用于一次维护接管，完成后移除；不得同时手工修改数据库结构。
- V2 仅增加 audit_events：actor_id（系统动作可空）、action、object_type/id、reason、JSONB 前后变化、带时区 occurred_at。索引支持对象和操作者追溯。不删除有审计关联的账号。
- AuditService 强制加入调用者事务；失败向上抛出并回滚，不异步、不另启事务。调用方按操作提供最小字段白名单，额外防御检查拒绝常见凭证字段（含嵌套），不能保证任意自由文本自动脱敏。此步没有公开审计接口，S02以后业务接入，S28提供管理员查询。
- request.js 保留既有 Error/message、401统一过期处理和 silent 行为，并新增 status/code/details；没有 HTTP 响应时 status=null，保留 Axios 网络/超时 code。服务端错误保持拒绝 Promise。

### 验收例与恢复

专用 studyroom_java_test 内隔离 schema 验证：空库安装；原 V1 结构且有用户/空间/座位/预约时升级数据不变；重复启动无重复版本；未知结构拒绝；损坏迁移可诊断且失败版本不写入；审计和业务同事务提交或回滚，敏感字段拒绝。旧预约并发与接口契约回归保留。前端检查 401/403/409、网络/超时和 silent/认证兼容，生产构建。登录接口使用 silent/skipAuthHandling，由登录页持久 alert 显示失败并保留输入，修复既有无令牌401无可见提示问题。

升级失败先保存具体版本及错误，检查是否事务回滚；不要删除卷、clean、改已发布 SQL 或盲目 repair。V2失败且V1/baseline成功时修复根因后重启；结构不吻合须人工核对备份与差异，不能自动抹平。正式恢复从升级前备份还原，由维护人另行执行。

## S02 校园角色与服务端权限

依据 v0.24 FR-06.1、BR-03/20/23、AC-18、规格4.3权限矩阵：学生与教职工为普通使用者，同一预约规则；统一管理员承担管理职责，不以管理员身份创建或操作普通预约（管理取消与补签按后续专用接口实现）。公共自注册关闭，账号由管理员维护导入，保留旧账号和历史注册记录。

实现边界：V3仅将users.role约束扩展为student/staff/admin，不修改既有身份和口令。AuthService统一识别合法角色，公共注册旧URL明确403而非创建校园身份；WebSecurity对所有/api/stats/*及/admin/*强制管理员，预约创建/本人动作及候补写入口只允许student/staff，服务内预约资格再次检查普通身份。登录、注销及禁用每次请求核查继续保留。未登录401、越权403，不把失败当成功。S03维护账号时接入本步审计基础。

前端store采用统一普通身份判断，路由、导航、首页、个人资料、未读消息及角色文字同步支持staff；登录页只保留登录，失败持久显示且可重试。管理员走管理主页；普通首页不调用管理统计接口、不用默认0冒充管理数据。没有修改旧信用/时间业务规则，生命周期切换仍由S07以后执行。

验收：student/staff登录后有相同普通导航、可合法预约，不能直接访问管理与所有统计；admin登录和管理统计可用，创建普通预约403；公共注册直接请求也拒绝且无新账号；注销/禁用后请求401；权限失败状态保持。前端构建、普通/管理入口及窄屏检查，真实数据库仅studyroom_java_test。

## S03 管理账号维护与本人联系方式

依赖S02提交9182c1a，依据正式规格v0.25 FR-06.1、BR-20/23、SC-02/07、PV-07与E-014。权限和原确认状态不变，仅将身份/联系方式落实为技术字段。

V4增加nullable UNIQUE campus_id(20)、phone(30)、email(254)，旧student_no原值映射，空值保持NULL，不伪造校园身份；旧列只读溯源，SeedData与唯一新写源改用campus_id。创建账号必须提供校园编号、用户名(3—50)、姓名、角色、6—64字符且不超过BCrypt72字节的初始口令；编辑可保留遗留未知编号，不提供新口令则保留原hash。手机号只作长度/空白规范化，不擅自限制地区；邮箱可空，非空格式校验。

管理POST /admin/users与PUT /admin/users/{id}，本人PATCH /auth/profile只允许phone/email，非白名单字段400，归属只从token取。账号列表、启停用等写路径收敛到UserService，迁出BookingService账号职责，不留下平行写源。管理写操作提供真实操作理由，审计同事务只收最小非凭证字段，失败回滚；旧状态接口同步前端/测试契约。本次不能禁用/降级当前操作管理员，防止本会话自行失去管理入口；并发唯一约束409、记录不存在404、未授权403。响应不返回password_hash/口令，审计不得保存凭证。

前端从AdminView拆UserManagement，真实加载/空态/重试、创建编辑弹窗、身份字段及理由、提交防重复，成功刷新列表与人数，失败保留输入。ProfileView增加本人联系方式表单，身份字段只读，保存更新auth。S04在此组件接入导入，不复制用户管理核心。

验收包括创建学生/教职工后真实登录、重复编号/用户名409无半成品、本人越权字段400且不变、双账号隔离、账号禁用会话失效、历史预约用户仍关联、审计失败业务回滚、响应/审计无凭证；迁移检查旧值与NULL保持。前端生产构建及桌面/窄屏真实操作，数据库仍只studyroom_java_test。AI-DEV-S03/E-DEV-S03对应实施方案与测试，课程人工PV不因自动测试而改通过。
