## S01 迁移与审计基础

关联 P40、BR-23、QN-04/06；不变更已确认业务规则、预约状态或权限矩阵。旧代码以 schema.sql 重复建表，缺少升级历史；request.js 丢弃 HTTP 状态。采用 Flyway 10.20.1（core 与 PostgreSQL 模块同版本），由显式 Flyway Bean 在返回前核对并迁移 public schema；避免 Boot 2 旧属性绑定与新版API差异。参考官方 [Spring Boot 迁移说明](https://docs.spring.io/spring-boot/docs/2.7.x/reference/html/howto.html) 与 [Flyway baseline 语义](https://documentation.red-gate.com/flyway/reference/commands/baseline)。本机 PostgreSQL17.11 集成与启动回归已通过。

- V1 固化原 schema.sql 的表、列、约束、索引及 mutex 初值；删除旧自动建表脚本，sql.init.mode=never，Flyway 为唯一结构升级入口。
- 空库执行 V1、V2；已有迁移历史校验 checksum 并执行增量；clean-disabled=true。
- 无历史的非空库默认拒绝。停服务并备份后，操作人显式设置 `studyroom.migration.adopt-legacy=true`，程序在同库事务内建立临时参考 schema，对比 V1 关系、列、默认值、约束、索引及额外触发器；不吻合则诊断并拒绝，不写 baseline。参考 schema 始终回滚。核对通过才标记 baseline 1 并执行 V2。该开关用于一次维护接管，完成后移除；不得同时手工修改数据库结构。
- V2 仅增加 audit_events：actor_id（系统动作可空）、action、object_type/id、reason、JSONB 前后变化、带时区 occurred_at。索引支持对象和操作者追溯。不删除有审计关联的账号。
- AuditService 强制加入调用者事务；失败向上抛出并回滚，不异步、不另启事务。调用方按操作提供最小字段白名单，额外防御检查拒绝常见凭证字段（含嵌套），不能保证任意自由文本自动脱敏。此步没有公开审计接口，S02以后业务接入，S28提供管理员查询。
- request.js 保留既有 Error/message、401统一过期处理和 silent 行为，并新增 status/code/details；没有 HTTP 响应时 status=null，保留 Axios 网络/超时 code。服务端错误保持拒绝 Promise。

### 验收例与恢复

专用 studyroom_java_test 内隔离 schema 验证：空库安装；原 V1 结构且有用户/空间/座位/预约时升级数据不变；重复启动无重复版本；未知结构拒绝；损坏迁移可诊断且失败版本不写入；审计和业务同事务提交或回滚，敏感字段拒绝。旧预约并发与接口契约回归保留。前端检查 401/403/409、网络/超时和 silent/认证兼容，生产构建。登录接口使用 silent/skipAuthHandling，由登录页持久 alert 显示失败并保留输入，修复既有无令牌401无可见提示问题。

升级失败先保存具体版本及错误，检查是否事务回滚；不要删除卷、clean、改已发布 SQL 或盲目 repair。V2失败且V1/baseline成功时修复根因后重启；结构不吻合须人工核对备份与差异，不能自动抹平。正式恢复从升级前备份还原，由维护人另行执行。
