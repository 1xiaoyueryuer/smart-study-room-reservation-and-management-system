F09，main，S24已实现及本轮验收，S25随后原位演进。基准正式v0.25 FR06.2、BR22/23、P35、AC20、SC07/PV07；唯一Java/Vue/Usage。已读用户报告约束，适用A2规则/A3模型/A5场景/A6实际验收/A7问题及B2/B4 AI证据，AI-DEV-S24/E-DEV-S24；原人工PV/现场/教师确认未验证，B5未布置。

## S24 决定及范围

2026-10-30用户对“管理资源提前终止但真实签到使用能否评价”回复“自行选择最合适的 选了之后根据要求改需求报告即可”。本轮分析采用允许：有唯一Usage实际签到且已结算结束的本人预约，正常completed或cancelled且termination_reason=admin_resource_change均可评价。理由：评价针对已发生的使用体验，资源提前终止不抹除事实。未签到取消/未使用结束/仍使用中不可评价。补签同一真实Usage核对；不加原需求没有的最低使用分钟数。此为用户授权自主采用，不倒写为用户逐项选定、校方或教师确认。

## S24 精确合同与职责

- ReviewService复用BookingService.detail先落实本人原生命周期，随后只读Usage及预约事实判资格；不复制签到或结束写源。启用student/staff且本人，管理员不得维护本人评分。全体写沿booking_mutex，资格/版本/唯一与审计同事务。
- GET /api/reservations/{id}/review → {reservation_id,eligibility:{can_review,blocked_by},review:null或公开本人Review,server_now}。Review={id,reservation_id,rating,content,version,created_at,updated_at}，明确offset时间。无公开/管理接口，S25再扩。
- POST同路径仅{operation_id,rating,content}创建；PUT仅上述+version修改。rating为真实JSON整数1..5，拒绝小数/字符串/boolean；content trim1..2000，version真实正整数。未知字段拒绝，不接受owner/room/管理字段。
- 新操作成功回执{operation_id,replayed,review}；持久review_operations保存actor/目标/action/规范request/首Review快照。成功旧UUID先纯读重放首快照，不顺带结算、改资格或覆盖后来修改；异actor/body/目标/action冲突409。正常新POST重复409，PUT无记录404、旧version409。请求未知冻结原目标/body/key，只主动原请求核对；成功后GET-only读当前版本。
- reviews每reservation唯一，owner由认证及真实预约取，DB复合FK守归属；review_operations同Review/actor归属。一个核心原位演进，不建v2。首次V21增量迁移，旧checksum不改。原Usage、预约、违规、限制不因评价写改变，正常读取的原生命周期收敛另记。
- MyReservationsView真实记录提供“评价/查看本人评价”入口，打开ReviewEditor请求服务端资格；5个可键盘radio、textarea、公开说明及真实创建/修改。对尚不合格明确原因，不能靠按钮判资格。不同预约草稿隔离，失败保输入、未知锁原请求、迟响应保护、成功回执guard。
