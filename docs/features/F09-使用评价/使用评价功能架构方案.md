## S24 决定及范围

2026-10-30用户对“管理资源提前终止但真实签到使用能否评价”回复“自行选择最合适的 选了之后根据要求改需求报告即可”。本轮分析采用允许：有唯一Usage实际签到且已结算结束的本人预约，正常completed或cancelled且termination_reason=admin_resource_change均可评价。理由：评价针对已发生的使用体验，资源提前终止不抹除事实。未签到取消/未使用结束/仍使用中不可评价。补签同一真实Usage核对；不加原需求没有的最低使用分钟数。此为用户授权自主采用，不倒写为用户逐项选定、校方或教师确认。

## S24 精确合同与职责

- ReviewService复用BookingService.detail先落实本人原生命周期，随后只读Usage及预约事实判资格；不复制签到或结束写源。启用student/staff且本人，管理员不得维护本人评分。全体写沿booking_mutex，资格/版本/唯一与审计同事务。
- GET /api/reservations/{id}/review → {reservation_id,eligibility:{can_review,blocked_by},review:null或公开本人Review,server_now}。Review={id,reservation_id,rating,content,version,created_at,updated_at}，明确offset时间。无公开/管理接口，S25再扩。
- POST同路径仅{operation_id,rating,content}创建；PUT仅上述+version修改。rating为真实JSON整数1..5，拒绝小数/字符串/boolean；content trim1..2000，version真实正整数。未知字段拒绝，不接受owner/room/管理字段。
- 新操作成功回执{operation_id,replayed,review}；持久review_operations保存actor/目标/action/规范request/首Review快照。成功旧UUID先纯读重放首快照，不顺带结算、改资格或覆盖后来修改；异actor/body/目标/action冲突409。正常新POST重复409，PUT无记录404、旧version409。请求未知冻结原目标/body/key，只主动原请求核对；成功后GET-only读当前版本。
- reviews每reservation唯一，owner由认证及真实预约取，DB复合FK守归属；review_operations同Review/actor归属。一个核心原位演进，不建v2。首次V21增量迁移，旧checksum不改。原Usage、预约、违规、限制不因评价写改变，正常读取的原生命周期收敛另记。
- MyReservationsView真实记录提供“评价/查看本人评价”入口，打开ReviewEditor请求服务端资格；5个可键盘radio、textarea、公开说明及真实创建/修改。对尚不合格明确原因，不能靠按钮判资格。不同预约草稿隔离，失败保输入、未知锁原请求、迟响应保护、成功回执guard。

## S25 管理回复、隐藏及公开去身份（已实现及本轮验收）

前置S24已5305500；FR06.2/06.5、BR22/23、P36、AC20、SC07/PV07、AI-DEV-S25/E-DEV-S25，继续按报告约束A2/3/5/6/7及B2/4同步。沿同一reviews和ReviewService，不新建另一评价核心；旧操作快照不改、旧V21不改checksum。

- 活跃管理员可独立回复（trim1..2000）或有理由隐藏（reason trim1..1000）。隐藏是保留原记录的可追溯状态，本步不新增删除/恢复公开；已隐藏仍保原评分文字、回复和理由，本人仍可查并修改自己的评分文字，但修改不得取消隐藏。管理员任何输入均不接受rating/content/owner等改评分字段。回复可再次修改，均留持久操作快照与审计；隐藏新操作已隐藏409，原成功UUID仍先纯读。
- 本人Review在S24字段外增加admin_reply、replied_at、hidden、hidden_reason、hidden_at；不含管理账号/原身份等额外资料。统一version用于本人修改和管理员操作，并发版本冲突不覆盖。旧S24首快照仍按原结构纯重放，不拼接后来的隐藏状态；GET为当前状态。
- GET /api/admin/reviews?page=1&page_size=20&room_id=&hidden= → {items,total,page,page_size,server_now}；page正整数，page_size1..50，hidden仅true/false/省略；稳定updated_at DESC,id DESC。管理员详情GET /api/admin/reviews/{id}返回同一管理条目：本人Review全部字段+room_id/room_name+subject{id,username,real_name,campus_id}。仅管理可读校园身份，列表与详情不返回password、整账号或使用私有核实。
- POST /api/admin/reviews/{id}/reply仅{operation_id,version,reply}；POST .../hide仅{operation_id,version,reason}。严格真实JSON正整数version/字符串，400多余字段或缺值，403普通人，404不存在，409版本/操作冲突。成功统一{operation_id,replayed,review}，review为当次本人安全Review快照；管理额外身份通过GET核对。未知保原目标/action/body/UUID主动核对；成功仅GET当前详情。
- 同booking_mutex，复核管理员、版本和状态；reviews、同一review_operations持久首快照、typed通知及审计同事务。V22原位扩review_operations的reply/hide动作及actor权限关联；须保原create/update仍同owner的数据库保护、actor外键、review/reservation关联及不可变快照，不得因管理员操作弱化原owner一致性。旧owner操作不重写。reviews原归属和创建时刻不能被管理操作改写。
- 管理回复/隐藏各生成本人typed通知，通知以review_reservation_id定位本人预约、review_operation_id对应唯一操作，复合FK保护接收人/目标/操作，一操作至多一通知；不公开管理私有数据。消息中文类别与跳转/mine?review_reservation_id=真实编号直接打开本人评价，深链仍走owner接口鉴权。本人更新不自动发给自己新通知。
- GET /api/rooms/{id}/reviews?page=1&page_size=20：沿现有校园登录权限向已认证用户公开可见评价，未登录仍401，不扩大互联网匿名访问。返回{items,total,page,page_size,server_now}；公开每条仅{id,rating,content,updated_at,admin_reply,replied_at}，明确offset，WHERE hidden=false在服务端过滤，总数只计可见，稳定updated_at DESC,id DESC。严禁返回user_id/username/real_name/campus_id/reservation_id/原预约时段/管理操作者/hidden_reason等身份或私密字段。用户自行在文字中填的内容不做虚假自动脱敏承诺，输入处提示勿填个人信息。
- 前端管理端lazy“评价管理”真实列表、筛选分页、详情及回复/隐藏分别确认；原评分只读。本人Editor展示回复/隐藏理由，并保自身修改入口及不恢复公开说明。新“空间评价”路由与导航/选空间真实列表展示匿名星级、文字、管理回复，失败保状态并显式重试；复用原组件，390/build必要。
