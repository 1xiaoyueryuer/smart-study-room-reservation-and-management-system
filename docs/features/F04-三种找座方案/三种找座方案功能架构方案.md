## 当前实现与模块职责

S11开工时BookingView仅输入统一date/start/end、Resource.seatMap只给某slot的occupied/合法二值，缺连续空档和本人跨空间扣除；不能把旧二值当推荐。OpeningScheduleService.Calendar一次读取空间座位/开放/例外/临停，day(date,seatId)是唯一合法开放权威；复用其输出。S10 Booking/Usage已统一到期事实与预约锁，S07 Slot保真历史秒/24。原SeatPlanDesk、SeatExplorer/3D模型及zone/power/window等属性、位置筛选继续复用。

## 数据、接口与流程

### S11基础API与快照（S12在下节扩策略）

GET `/api/availability?room_id=<id>&date=YYYY-MM-DD&strategy=earliest`。登录普通用户；uid仅取认证，不收user_id。room/date必填，strategy仅省略（null）默认earliest，显式空串400；S11交付时仅支持earliest，longest/duration当时明确400；当前扩展遵照下节S12，非法策略始终400不假成功。日期按同一BookingPolicy的校园D..D+2，资源不存在404；空间存在但停用/闭馆返回真实room与无可约片段，不静默换空间。

返回对象：room、date、strategy、server_now、campus_today、computed_at、campus_zone、seats、results；server_now/computed_at为一次Clock抓取并截PG微秒的同一校园now（明确+08，Asia/Shanghai），Policy原位validateDate(date,now)复用该值，BookingPolicy自身now也统一截MICROS与Booking/Usage一致；这是V-45跨消费者精度续修的设计预审，不是新增500事故，S11在32相关、120全套及最后9相关中已验证，本轮真实页面也通过。room与seats仅公开资源安全字段，旧未知位置保持真实null；seat包括id/room_id/seat_no/row_no/col_no/zone/has_power/near_window/status及适用资源原因、真实opening_windows/closed_reasons，available_windows每项与results为同一完整shape，不返回用户身份、预约对象或码值；无统一slot，API不造bookable_for_slot/occupied模糊字段。room保持所选date开放/理由及既有容量定义，容量不是空档数量。

每条results/available_windows片段固定字段：seat_id、seat_no、room_id、room_name、building、floor、location、row_no、col_no、available_start、available_end、duration_minutes、wait_minutes。start/end为HH:mm，end支持24:00、start不可24；每个真实片段一条，同seat多片段全部保留。wait_minutes=ceil((该片段start-同一now)秒/60)，最小0，明确为等待分钟；duration是合法整分钟区间差，不能将占用前后碎片相加。

### 统一空档算法

1. 在booking_mutex同锁事务以单now先调用Booking现有统一结算，Booking.reconcileAvailability(uid,room,date,同now)批查所选日selectedroom或uid本人跨空间pending/checked_in并复用原reconcileRows，不另写自动结束或忽略已到期事实。
2. 批量读取所选room全部座位、有效座位预约和本人所选日所有空间的有效预约；本人查询不能被room过滤。终态不占用，最终创建仍再重查。避免按seat逐条SQL；Opening.calendar仅加载一次所选room。
3. 每seat取Opening.day(date,seatId)合法windows（含例外覆盖、空间/座位启停、多原因临停并集），扣除座位有效预约与本人全部空间安排的并集。占用先合并重叠/相接再求差，严格左闭右开，首尾相接可约。
4. 历史预约先用Slot.endpoint真实秒/小数求差，差后start向上ceil分钟、end向下floor分钟；当日再截到ceil(now)，后两天不错误截到今日时分。只保留end-start>=30，24只当日右边界；不把22—次日02解释成跨夜新约。今天23:59:30无合法30分钟时返回空，不自动改日。
5. earliest稳定排序为(available_start,位置字段字符串,seat_no,seat_id,available_end)。位置依building/floor/location/room_name，排序将null作为空串但响应不伪填；floor不转正整数，seat_no用一致字符串比较，ID兜底。computed_at和全部结果共用同now，不用浏览器UTC或每seat不同Clock。

### 图列表和预约闭环

BookingView保留日期/空间及楼栋楼层位置筛选，默认突出最早结果，不自动预约或强制预选。同一response切换图/列表，座位点开available_windows，片段key含seat+start+end；完整空档与本次选择分明。默认本次起点=所选片段start、结束=start+30分钟，可在完整片段内改整分钟起止；这是交互默认，不是新增30分钟上限，不影响241/更长合法预约。

选择/确认快照含seat、完整window、本次实际start/end和computed_at；禁止仅selectedId代表同seat多片段。确认/POST期间锁条件，同现有真实createReservation提交；服务端对日期、资格、开放、本人/座位冲突再检查。被抢409持久显示并同room/date/策略刷新，时间已过等400亦如实反馈和刷新，不换场所日期；刷新后不静默沿用无效片段。

复用2D/3D外观和选择组件，明确“可选空档”与“本次时段”语义。旧bookable_for_slot/occupied原是某统一slot的判定，不能直接赋值haswindow再称全天可用；适配层以当前所选片段/实际起止判定最终可提交，3D也走同一选择/确认函数，无第二套提交。加载/真实空结果/错误/重试和旧响应序列控制清楚，窄屏图可容器内滚动而不使页面外溢。

### S12 固定实现契约（2026-10-30，工程/本轮真实页面完成）

依赖S11 119bfe7，关联FR-04.2/04.3与FR-04.1/04.4/FR-02，P20/P21，BR-02—06/23，AC-01—04/09/13、UC-01、SC-01/PV-01。同一Availability差集/同now/合法片段/本人跨空间扣除与最终POST规则不变，只扩排序/过滤和清楚的建议交互；不新表、不平行算法，不新增人工校方确认。

**请求与响应：** GET `/api/availability`支持strategy=earliest/longest/duration；仅省略null默认earliest，空串/非法400。required_minutes只在duration必填，原始值严格ASCII十进制整数字符串（[0-9]+），>=30；空、29、负数、显式加号、小数、科学记法、NaN或Java int溢出400，不接受隐式Number转换纠正用户输入。前导0按十进制解析并回显规范整数；int最大2147483647只属解析边界，非业务时长上限。合法整数量值可超全天能力，此时返回真实空结果，不新增240/480上限或擅改条件。非duration只要附required_minutes（含空串）明确400，客户端保留输入值但不附请求，避免悄悄忽略条件。response.required_minutes为duration请求数值，其他null；若参数非法，无结算/业务写入应在基础请求校验后才进入数据查询。

results及每seat.available_windows继续同一完整shape，保留完整available_start/end、duration_minutes、wait_minutes/位置字段，再新增suggested_start、suggested_end（HH:mm/end可24）。earliest和longest建议为完整gap起点至起点+30分钟，duration建议起点至起点+required；仅对筛选通过片段计算suggested_end以免大整数溢出；完整gap不因建议而截短，不将建议结束误当可用结束。原4参find仅薄适配至新增原始参数同一核心，不形成平行算法。

**策略与稳定顺序：** 三策略先调用完全相同的合法差集；earliest沿原稳定(start,位置字符串,seat_no,id,end)。longest按单段duration_minutes降序后沿earliest全部兜底；duration筛单段duration>=required后沿earliest，不拼碎片。排序/过滤后的results和seat.available_windows完全一致，未满足短窗不能残留图里；available_windows按该策略对应结果顺序，图/列表/2D3D共用同一返回，不另在客户端用当前页假全量排序。

**建议、用户实际选择与预约：** “所需时长”是找座筛选与建议，不成为预约后端新增硬门槛；沿BR-05用户可在合法空档内自选>=30分钟。duration选片段默认实际起止精确等于suggested_start/end，即requested分钟；用户主动改短仍合法时可提交，但编辑处和确认均明确“本次30分钟，短于找座时输入的120分钟”，不能继续称本次满足120。若实际更长且在完整gap内允许，不因原所需值设上限。earliest/longest仍默认30可改；完整空档、建议区间、本次实际区间三者区分，longest不暗示自动占满整段。

**模式切换与失败恢复：** UI三方案有清楚排序说明，duration显示分钟输入。切策略保date/room/位置及required原输入，清当前片段/实际起止并请求新策略；改required同样使旧选片段失效、重新查询，快速输入/切换由序列/请求快照隔离旧响应。snapshot含strategy/required、seat/window/建议/实际起止/computed_at，确认/提交锁定条件；真实POST仍只按日期/资格/开放/本人座位冲突及min30规则重查，不把required发成预约限制。无结果明确“没有满足120分钟的连续空档”等真实条件，不自动换日/房间/时长；非法输入持久反馈可改正，禁止将旧结果假作当前查询成功，409同条件刷新/清失效选择。2D3D相同默认/编辑/确认提示与最终提交函数，不造平行核心。
