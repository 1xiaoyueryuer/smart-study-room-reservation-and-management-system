## 目标、范围与验收

管理员修改资源前看真实影响，确认后按管理原因取消整条受影响预约，使用中按确认时刻结算已用、通知且不记用户违约。包括未来临停覆盖当前使用后半段，也在确认时立即终止，不新增计划终止/部分续用；预览突出“确认将立即取消整条预约并按确认时刻结算；如需继续使用请稍后确认”。恢复开放不复活旧预约，历史禁删不放宽。

该时点沿UC-05“确认后按管理原因取消”及ST-12“资源管理确认终止”目标cancelled细化，依据用户K-DEV-03采纳推荐/合理自主修订授权，不是新校方或人工逐项确认。使用中须有管理员自报已现场协调的明确确认和说明；系统只记录自报，不核实物理到场/腾退，接口成功不宣称现场已恢复。

## 当前实现与模块职责

S13开工时Resource.save/updateSeat对停用/移动调用ensureNoActive，Opening.save/deleteException/saveBlock写后ensureProtected拒影响；cancelBlock恢复直接写。ResourceManagement的saveRoom/saveSeat、OpeningManagement的saveSchedule(remove)/saveBlock/cancelBlock都须接同一预览确认，不能只接停用按钮。

新room/seat/空房batch无已有预约影响可保原路径；deleteRoom按原房间预约/候补/房间停用历史硬拒；deleteSeat只按自身预约/自身临停历史硬拒，不因房间无座位归属的候补禁删全部空座。曾递补座位的预约自然保护该seat；不能通过预览取消后删除。座位码轮换独立，不属本次预约影响变更。纯说明/资源属性与合法布局扩张不取消；楼栋/楼层/location移动或seat_no/行列移动仍显式影响有效预约承诺。

ResourceChangeService/Controller负责编排，纯normalization/project复用Resource/Opening校验和Calendar.day，不写后rollback伪预览、不另造开放规则。确认先明确取消受影响预约，再调用原Resource/Opening写方法，让剩余预约仍过原guard；不删除guard、不收force/bypass、不反注入Resource→Booking→Opening循环。UsageService仍唯一使用写源。

## 数据、接口与流程

### V10持久依据与权限

V10增加资源变更操作记录（operation_id唯一UUID、actor、规范proposal/impact与请求指纹、coordination私有说明/固定source、成功结果和时间），同事务提交以恢复网络未知请求；无孤立成功或失败半成品。reservations新增可空termination_note<=1000，存本次公开payload.reason的取消依据快照，旧行保持null；termination_reason种类tag与note说明分开，不构成平行使用源。后续room.reason变更不能覆盖本人取消依据。

仅启用admin可preview/confirm；普通401/403与对象404真实返回。所有DTO整数域统一禁Jackson浮点转整数（accept-float-as-int=false），fraction不能静默截Long/Int；不影响Usage BigDecimal小数秒、普通Map浮点或序列化。proposal只接受七种已知type和对应DTO白名单，拒绝无效版本/理由、跨对象引用/越界/重复编号及旧daily写入，不根据客户端任意路径执行。公开资源reason仍沿原约束，coordination说明仅私有operation/audit，普通mine/detail返回termination_note与真usage，不返回私有自报内容。

### 最简proposal及API

proposal固定`{change_type,target_id,payload}`，payload复用现有DTO/version/reason：

| change_type | target_id | payload/行为 |
|---|---|---|
| room.update | room id | 原Requests.Room更新 |
| seat.update | seat id | 原Requests.Seat更新，归属room从DB取 |
| opening.save | room id | 原OpeningChange星期或日期窗口 |
| opening.delete_exception | room id | 原OpeningDelete，恢复星期安排也须算影响 |
| block.create | room id | 原Unavailability，seat_id可空 |
| block.update | block id | 原Unavailability，归属room从DB取 |
| block.cancel | block id | 原ResourceDelete版本/理由，解除一条不解除其他 |

POST `/api/admin/resource-changes/preview` body即平铺proposal。返回normalized_proposal、target_label、versions、impact_hash、pending[]、in_use[]、summary、server_now、campus_zone。versions为room_id/room_version，可选seat_id/seat_version或block_id/block_version；impact行安全字段reservation_id/user_id/real_name/seat_id/seat_no/date/start_time/end_time/status/checkin_at（来自Usage或null），不含凭证/联系方式。 target_label由已读真实上下文生成：room/opening为房间名，seat含room/原编号，block.update/cancel含room/原座位或全空间/原起止，block.create用新范围/起止；其上下文已受资源版本绑定，不单列新权威字段、不改hash身份语义，不含私有协调说明。summary含pending_count/in_use_count/total_count、immediate_termination=true及立即取消警示。

POST `/api/admin/resource-changes/confirm` body为`{proposal:normalized_proposal,impact_hash,operation_id,coordination?}`。coordination仅in_use非空时强制`{confirmed:true,note:trim后非空<=1000}`；source由服务固定admin_self_report，客户端不能声称系统核实。无在用不伪要求现场协调。协调是管理员自报满足guard，不由AI填测试字段冒充真实学生/校方现场确认；工程fixture必须注明模拟。

成功返回operation_id/change_type/target_id/room_id/cancelled_count/pending_cancelled_count/in_use_cancelled_count/cancelled_reservations/resource_result/versions/coordination_source/replayed。cancelled行含reservation_id/status/termination_reason/termination_note/ended_at/usage_record；首成功replayed=false，同请求已成功返回原业务结果并附true，不新增业务写/通知/审计。

### 只读投影、剩余影响与时间

preview用readOnly REPEATABLE_READ，不锁booking_mutex、不settle或写资源/预约/审计；纯拷贝候选Calendar/资源投影，共用原normalizer/day逻辑。未确认/取消对话框零写。校验与效果根据真实现状计算，不因已有代码guard推翻BR。

仍有效pending必须未到15分钟deadline，checked_in必须未到原end且真usage存在/未结束；pending必须无usage。纯状态一致检查由project与cancelcore共用，矛盾诊断拒绝，不补造使用事实。二者remaining均为max(plannedStart,同微秒now)..plannedEnd；结束为空或到期者不当管理取消对象。用同一纯remaining函数供投影和原Opening保护，避免只删过去开放段误伤窗口内pending；不更改签到截止或处罚。位置/编号/行列移动仍显式影响，不仅比较时间。

开放类变更比较旧合法remaining片段与候选新投影，丢失未来实际受保护部分才影响；覆盖星期所有有效预约日期、删除例外/过去起始临停/跨日/重叠多原因，不能只查当前D..D+2或只看block文本重叠。已过去改变不机械取消；布局仍不得缩到现座位bounds之外或删除有历史资源。

impact_hash绑定规范proposal/reason、资源版本与稳定排序影响集合（id/uid/seat/date/原端点/status/真usage checkin），不包含每秒变化now/增长duration。confirm同booking_mutex抓一次微秒now重算；版本/影响集合/状态或跨deadline/end变化则409且零执行，不先settle再throw模糊回滚。elapsed本身不导致永远stale，边界导致分类变化必须重新预览。

### 确认事务与幂等

先auth/规范请求，持锁后查operation成功记录，再作当前投影版本校验；同actor+normalizedproposal+原impact_hash+coordination请求指纹匹配则返回原结果，异actor或同key不同内容409，不因已成功后的资源version递增阻断正确重放。

首次确认hash一致且协调guard通过后，逐条调用Booking管理取消：pending→cancelled、usage保持null；checked_in→cancelled并Usage.finish(confirmNow,原end,admin_resource_change,同settledNow)，不写completed冒充ST-12。两者termination_reason=admin_resource_change，termination_note为公开资源reason快照；无新增违规/信用。所有取消/使用/通知/审计与原资源写入及operation成功记录同TX；任一失败全部回滚。先取消再原写guard仍保护未受影响剩余预约，无force后门。

恢复开放只改资源，不复活取消预约。通知包含允许公开的真实管理原因，协调note仅私有日志。期满事实在预览/旧hash失败不写，后续统一Booking生命周期处理，不能把已超期限者倒造管理取消免罚或凭管理事件多罚。

### 前端闭环

ResourceManagement及OpeningManagement上述全部七类动作提交时先preview，共享确认组件首先展示target_label和可读类型化变更摘要：room启停/位置/布局、seat编号/行列/状态、opening星期或日期/分段或闭馆、删除例外恢复星期、临停起止及范围；block.cancel必须显示原真实区间/范围，不能只type/ID/理由。原始JSON/版本hash可折叠排查，不能是唯一审阅内容。再展示待签到与使用中名单、立即终止提示。编辑原输入保留，未确认可取消；使用中明确勾选“我已现场协调并确认立即终止”并写自报情况，source标管理员自报，不称系统证明已腾退。本人取消页显示管理标签/termination_note原依据及真实usage，后续原因变更不丢历史。

提交/结果未知锁定proposal/hash/operation_id/coordination，不允许换预览上下文；未知只由用户主动按同key重试，不自动重放。409为已知失败可重取预览核对；成功后父列表reload失败明确“操作已完成，刷新待核”，不重提操作。复用SDialog，局部提交/未知锁时closeOnEscape=false，默认组件行为不全改；异步/窄屏/错误持久恢复完整。
