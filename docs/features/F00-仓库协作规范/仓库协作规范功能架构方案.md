# 仓库协作规范功能架构方案

- 功能：F00-仓库协作规范；操作者：仓库负责人 D / @1xiaoyueryuer。
- 分支：member/d。范围：仓库规则、文档入口与模板、轻量检查、CI、PR 模板及固定成员分支初始化，不修改业务行为。
- 授权：用户要求参考本机 se-course-team-11 构建类似仓库，便于后续代码修改；本次由该请求授权初始化，A/B/C 真实身份不作推定。
- 状态：可实施。

## 目标与验收

在已发布 v1.0.0-postgresql 基线上建立 main + member/a～member/d 协作结构。新增功能先写两份简明方案，再连续实施、验证、自查，中文提交、PR 人工审核和普通合并。首版标签与当前运行系统保持可用。

## 现有实现与适配

已有 Java17 / Spring Boot、Vue3、Docker PostgreSQL17、Redis、14项后端测试和28项接口检查，不复制参考仓库的问答业务、未知技术栈和知识库任务。以当前真实文件路径标记前端、核心后端、配套业务及工程边界；共享 Java 类按任务协调，暂不为分工拆代码。

## 规则与文档

AGENTS.md 是智能体入口，CONTRIBUTING.md 是 Git 和审核流程，docs/README.md 管理文档位置，docs/团队分工.md 管理成员与路径。功能默认只有架构方案、代码实施方案，测试证据复用已有目录；原作者资料维持来源标记。新增检查仅校验分支、标题、目录、方案配对及禁止提交本地配置，不声称实现权限隔离或替代人工审核。

## 验证与外部状态

用 Python 标准库测试合法/非法分支、中文标题、成对方案和本地配置排除，再执行实际仓库检查及差异检查。保留已有 Java/Vue CI。远端建立四个固定分支，配置普通合并、保留分支，通过 member/d -> main PR 交付；不自批、不自合并。main 保护、成员账号与独立审核人需明确配置后才能称已启用。
