# 统计与整体验收功能架构方案

F11/S29—31实施前合同。S28实施中，以下尚未实现或验收。依据FR07、规格3.3、P37—39、AC19、SC07/PV07与QN01—07，原人工PV、校园现场及真实手机实扫不因工程结果追认为通过，B5未布置。用户本轮允许适合项目的分析选择并修订正式需求；近七日选择校园当天及前六日，记为授权分析细化，不冒教师/校方确认。

## S29 唯一统计事实与快照

StatsService原位成为唯一聚合权威，复用Usage/OpeningScheduleService，readOnly/RepeatableRead。单次响应只捕获一个Clock instant（Asia/Shanghai），所有当前值与截时都传同snapshot_at，禁止子方法重新取now或前端本地时刻冒数据时间。仅active管理员，aggregate响应无个人身份/私有明细。筛选room_id正整数（不存在404、停用历史仍可读）、date正四位年ISO校园自然日（默认snapshot当天），未知参数400。全校room未填，当前指标与所选日指标分别说明；近七日始终snapshot校园当天及前六天，与选日热力图区分。

GET /api/stats/overview统一返回snapshot_at、campus_zone、scope={room_id,selected_date,trend_from,trend_to}、day、current、trend、peak、top_seats。day及trend每项：created_count、cancelled_count、checkin_count、usage_seconds、active_violation_count（trend另date）。current：open_available_seats、in_use_now、usage_ratio、complaint_todo_count、complaint_awaiting_count。peak按近七日24小时分格展示使用秒数/签到人次；top_seats按同范围实际使用秒数降序，房间/座位编号稳定并列序，最多10项，无个人身份。保必要旧Java/HTTP薄入口时必须调用同一聚合引擎并有明确当前契约；同一步适配全部前端/脚本调用者，不能同时保旧14日与新7日两套事实算法。

| 指标 | 唯一口径 |
|---|---|
| 成功创建 | reservations.created_at落日内的成功记录，含后来取消，不按res_date或当前status剔历史；无效提交不计 |
| 当日取消 | status=cancelled且真实ended_at落日内，含管理取消；不以created_at猜取消时刻，旧未知不伪造 |
| 签到人次 | 唯一usage_records.checkin_at落日内的记录次数，不称去重人数；未签到无Usage不计 |
| 使用秒数 | [checkin_at,min(真实ended_at或snapshot,预约计划结束))，保微秒，反向数据不作0吞掉；按校园午夜/小时交集切分，管理提前终止/提前签退按真实结束，不称真实物理停留 |
| 有效违规 | violations.status=active且occurred_at落日内；提醒非违规表，已撤销不计；不从预约终态/信用分重算 |
| 投诉待办 | 当前存储生命周期submitted+processing，awaiting_confirmation另列，依据同一DB快照；不由统计接口执行处罚/到期状态写入 |
| 当前比例 | snapshot当下实际开放、可用且未临停座位集合为分母；分子为该集合中未结束且原计划未到期的真实Usage座位。分母0返回null，显示不适用；其他0仍真实0 |

没有可还原的当日历史容量时移除旧历史时长利用率，近七日图用次数与使用小时，不用当前配置冒过去容量。热力图为真实Usage与时间片相交的0/1记录，不称占用概率。GET /stats/heatmap沿同权限/日期、单snapshot，返回24小时明确片段及全部历史座位使用（停用资源保留），不因当前开放窗口删掉过去实际使用，不推算历史容量。日期由校园时区计算，不用UTC toISOString截日。

AnalyticsView沿现ECharts/指标卡原位改图例与帮助，显示所选日/当前/七日范围和真实服务时间，0与null分别呈现；HomeView等所有旧overview消费者同步。加载/空/失败重试与最后成功快照先具备；S30再上10秒调度，不提前冒完成。专项对账创建日≠预约日、取消历史、未签到、提前签退/管理终止、工程历史跨日分割、撤销/提醒、两类投诉、开放/临停边界、零分母及管理权限。GUI与正式三报告/E014/模型映射随实际维护。

## S30 十秒刷新与失败恢复

页面活跃/可见时每10秒发起overview和当前heatmap资源读取，同一资源请求不重叠；筛选变化保最后成功快照及其scope，序号/查询身份拒绝旧响应，必要时只排队最后筛选。成功刷新替换数据与snapshot_at，失败保旧值/旧scope/旧snapshot，首次无成功明确尚未读取，不能失败归0或改数据时间。错误及手动重试可操作；离页清定时器/监听/失效请求，隐藏暂停，恢复再取；各图不串用不同资源快照。后台异常保持真实状态/错误，不用成功壳0值吞依赖失败。业务调度器与页面统计刷新职责分开。

验收至少观察3轮，503或受控失败保旧值与原时间、恢复真实GET重试，快速换空间/日期旧请求不覆盖、卸载无后续轮询、零分母仍不适用。工程受控故障与真实断网区分，缺真实手机/网络环境不伪造通过。

## S31 整体验收与教学性能

按P01—40/AC01—21/QN对照已有真实接口、页面和测试，更新旧半小时/信用/暂离/候补脚本断言但保并发/权限；工程模拟全链路找座预约、码签到/结束评价、被占投诉/核实违规/限制/申诉重算/资源善后，角色及窄屏逐页验证。手机实扫/校园硬件/独立人工PV未执行明示未验，不用模拟替代。

独立studyroom_java_test构造1000模拟座位，30×20与20×20两个房间均不超单房30×30；全1000地图查询与成功预约提交分别至少20样本，HTTP及JSON解码计时、登录和限流间隔不计入单样本，报告最近秩ceil(0.95n)的p95及2秒教学目标、机器/版本、样本与失败。查询可每样本顺序取两房合计1000，明确不是单房600的成绩；单客户端本机不冒校园高并发容量。失败保原测量，不能删慢样本凑达标。预约最终取消保测试历史，不对开发库清理。

适当最后完整后端/前端/生产构建及必要smoke，修真实缺陷再验对应范围。原F方案、docs/VALIDATION.md与既有证据索引原位回写，不新增重复完成报告；仅有重复执行不造空commit。每步有意义结果各中文本地commit，不push。
