# 投诉核实反馈功能架构方案

- 功能：F06投诉核实反馈，S14本人求助投诉与可选材料；S15管理受理核实提醒、S16反馈确认异议/七天结案、S17处理目标后续按原计划实施。
- 主责/协作：root集成，backend/frontend同任务子agent分目录，文档子agent维护本阶段/正式资料；用户已授权并行，无独立人工审核。
- 分支/范围：main，唯一Java/Vue核心、V11及相关测试/文档，root管README/MIGRATION/scripts。不push、不改历史、不清开发库。
- 依据：S13 499c0f8；规格v0.25 FR-06.3、BR-12/13/19/23、UC-03、AC-18、SC-04/PV-04、原P23/S14及E-008 S1/S8，E-012 P04/P05。
- 状态：S14完整合同已与root/backend/frontend对齐，工程175全套/package及本轮真实GUI/下载API/权限完成，待本地提交；S15—17仅范围总览，不预建业务接口/字段。
- 报告约束：适用A.2来源性质/技术候选、A.3/A.4模型权限、A.6实际验证、A.7问题/A.8责任及B.2/B.4交互；AI-DEV-S14/E-DEV-S14复用本阶段。原人工确认/PV/校方不追改，B5未另布置/B.3不适用。

## 目标、范围与验收

普通学生/教职工从本人预约（含历史）发起被占求助，或独立提交一般service，可附受控图片或仅文字；成功为submitted/待受理，本人可刷新列表/详情/附件。不是已受理、材料已核实或现场恢复。投诉不延长签到期限、撤销违规或复活释放的预约；不让普通用户猜占用者ID。

FR-06.3/UC-03/E-008 S1只要求关联本人预约，S8保留错过签到说明与核实纠错；本步允许历史作为证据关联，不擅加仍有效门槛。service可无预约，也可关联本人预约；有关联时room/seat由预约导出，不匹配room400。service无预约可选真实room，完全无关联也可文字提交。

| FR-06.3、AC-18 | occupation本人历史/他人/无预约，service无/可选本人预约或room | 本人历史可提交不恢复、不延期；他人拒、occupation缺预约拒，关联room不匹配400 | 真实DB/HTTP与本人页面 |

## 当前实现与模块职责

开工时无complaints/事件/材料领域或投诉入口；已有Mine、路由布局、SInput/SSelect/SDialog/SButton、统一错误链与Bearer blob可复用。图片上传不同于S09本地二维码解码，本步需要实际服务器内容/暂存/绑定/清理；不以页面文件名或本地预览冒充已保存。

ComplaintService负责本人提交/幂等/上下文快照/查询，AttachmentService负责bytea、图片检查/鉴权内容和临时cleanup；Store为唯一DB入口，AuditService同TX。使用booking_mutex串行提交与cleanup，复用studyroom.scheduler-enabled开关；不调用Booking/detail作内部快照结算，不延期或复活。S14只created/event/bind/audit，无新增提交通知，不假称已通知管理员或受理；后续通知随真实处理动作实现。

## 数据、接口与流程

### V11与安全数据

本步只建complaints、complaint_events、受控complaint_attachments：投诉含owner、operation_id UUID唯一/request_hash、type、status=submitted、trim说明、可空reservation/room、context_snapshot、submitted_at；事件仅submitted/source=user_submit及时间，附件含UUID/owner/可空绑定complaint、受控bytes/安全metadata/暂存到期。不得预造受理人、反馈、deadline或提醒业务；后续步骤原位演进。

请求operation_id由客户端生成，持久绑定同owner规范请求，已成功先查既有结果再校验附件/当前关联，避免重放被已绑定附件误拒；同key异body/actor409，不返回他人旧结果。创建投诉、submitted事件、绑定本人有效未绑材料、审计同事务，任何失败全回滚，不重复投诉/事件或半绑定。审计只必要id/type/status/关联及附件计数，不写图片bytes、口令或私密原文堆积。

context_snapshot在提交时从真实关联DAO读取并持久化，不信客户端名称/状态，不调用Booking结算：

- 有reservation：reservation_id/room_id/room_name/seat_id/seat_no/date/start_time/end_time/status_at_submission/building/floor/location。
- 无res仅room：room_id/room_name/building/floor/location。
- 无关联：null。未知位置保持null，status是提交时记录原值，不把该快照当现场核实或有效资格认定；后续改资源不抹原提交上下文。

### 请求与返回

所有业务路径均`/api`，普通active student/staff可上传/提交/本人读；管理员只可读取已绑定且有管理权限的附件，不新增管理处理入口。匿名401、无权限403/对象不存在404沿统一错误链，不收owner_id/占用者ID/任意文件路径。

| 方法/路径 | 输入 | 返回/语义 |
|---|---|---|
| POST /api/complaint-attachments | multipart file，仅一个 | id(UUID)/display_name安全生成/content_type/size_bytes/width/height/sha256/created_at/expires_at；真实存bytea成功才标uploaded |
| GET /api/complaint-attachments/{uuid}/content | Bearer | owner未过期临时，或owner已绑定/授权admin已绑定可取；no-store/nosniff及安全生成文件名，不公开静态URL |
| POST /api/complaints | type occupation或service、可空reservation_id/room_id、description、attachment_ids UUID[]、operation_id UUID | 完整detail并附replayed；首false/重放true，未知不能假成功 |
| GET /api/complaints/mine | 无可控user_id | 本人基本字段及attachment_count数组，无events/bytes，详情另取 |
| GET /api/complaints/{id} | id | 本人完整detail，不得取他人私密记录 |

完整detail固定id/operation_id/type/status(submitted)/description/reservation_id/room_id/context_snapshot/submitted_at/attachment_count/attachments安全metadata/events；events为{id,type:submitted,created_at,source:user_submit}，无未来处理事实。metadata/submitted/event时间统一带+08校园ISO，context date/start/end保持原DB文本（含24/秒小数）。绑定后的metadata expires_at=null，不把已绑定材料标待清理。无附件数组正常，不提供删除附件或上传幂等接口。

### 输入边界、内容和临时清理

以下是本轮用户授权下工程参数，原材料只确认照片可选/隐私，不冒充业务方人工确认数字：description trim后1—2000字符，最多3个不重复UUID材料；每张真实PNG/JPEG<=5MiB，单边<=10000、总像素<=20,000,000。服务端检查实际签名/完整PNG或JPEG容器/可解码内容/尺寸/字节，V-53不能把ImageIO恢复不完整图当成功；不能只信扩展名/声明MIME；保上传原bytes/hash，不转换图片或声称材料已核实。display_name由服务生成material-uuid.png/jpg，不把原名当路径或HTML。

传输multipart max-file-size=6MB/max-request-size=7MB，业务仍5MiB，保CSV既有1MiB服务校验；传输边界以随机端口真实HTTP验证，不把MockMultipart当servlet上限实测；不照搬S09二维码4096²限值。附件只受控bytea/鉴权读取，前端Bearer blob/ObjectURL、安全文本显示并及时释放。

暂存24小时只清expires<=now且未绑定材料，已绑定永久历史本步不清；下载/绑定实时判过期，不靠任务延迟伪有效。cleanup与提交同mutex，边界竞争有确定结果，无绑后被清理；任务随现scheduler开关，不向开发库做清空测试。无新DELETE/上传幂等：本地移除只移队列，未知上传不假成功；重试可能产生未拿ID的暂存，由24h cleanup回收，不删除绑定历史。

### 前端真实闭环与未知恢复

普通导航/complaints为表单+本人列表，/complaints/:id详情；Mine任意本人历史行独立求助入口，不把投诉列成会改变预约状态的生命周期动作。occupation带入/选择本人预约并显示真实关联；service可无预约/可选room或本人预约，不要求猜对方身份。文字、上传队列queued/uploaded/error保存，全部本次选中材料成功才允许create；失败保文字/材料，可显式本地移除或重试，不自动漏失败图提交。

create未知结果冻结规范body/operation_id/材料ID/上下文，只主动同key重试；已成功但刷新失败明确已提交、重取详情，不重提。响应详情来自真实接口，可查看submitted事件/context/受控图片；无图/空列表/加载/失败重试/权限/窄屏完整。成功只能写待受理，不预造受理/提醒/反馈按钮或目标倒计时。
