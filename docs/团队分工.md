后端目前是单包 cn.studyroom，未按功能拆包，因此边界按“功能 + 本次实际文件/方法”分配，不按纸面分工预先拆包，也不为边界造备用实现。实际任务在功能方案中写明本次允许修改的文件；超出范围按跨模块规则处理。

| 共享文件 | 统筹 | 协调方式 |
|---|---|---|
| Requests.java、Api.java、ApiController.java、Store.java | B 统筹业务契约 | 接口或数据结构变化先说明影响；涉及前端契约同步告知 A |
| DatabaseMigrations.java、database/init/ | B 定业务数据规则、D 定工程执行 | 迁移与初始化脚本随功能一起交付，D 核对执行与回滚说明 |
| backend/pom.xml、frontend/package.json、锁文件 | 各自模块成员 | 依赖变更说明原因与影响，不在同一 PR 顺手升级无关依赖 |
| .github/、AGENTS.md、CONTRIBUTING.md、docs/README.md、docs/templates/、scripts/ | D | A/B/C 需要调整这些文件时先在 PR 说明理由，由 D 审核 |
| docs/requirements/、docs/reports/、docs/evidence/ | 按章节/条目分配本次编辑者 | 同一文件多人协作时分段修改，避免整篇重写 |
