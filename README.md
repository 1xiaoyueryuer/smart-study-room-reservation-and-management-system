# Smart Study Room Reservation and Management System

智慧自习室预约与管理系统。当前基线版本：**v1.0.0-postgresql（Java + PostgreSQL）**。后续需求实现继续在本项目迭代；此版本通过 Git 标签保留，源码快照不含个人口令、运行日志或本机工具配置。

基于 [imicola/smart-study-room](https://github.com/imicola/smart-study-room) 的课程项目二次开发：保留原 Vue 3 前端，后端改为 Java 17 + Spring Boot，使用 Docker PostgreSQL 17 和已有 Redis，已移除智能助手。保留原作者 MIT 许可证。

当前已接入校园账号、开放安排、预约签到与使用结算、三种连续空档找座方案、资源变更善后，以及投诉材料、管理核实、独立提醒、反馈确认结案、处理目标提示、核实事件的手动违规登记，以及独立预约限制、30天累计触发、统一资格和本人申诉、审核与违规限制重算。核实补签也已接入；本人使用评价已接入；评价管理回复隐藏及校园公开也已接入；后续记录查询、消息整合和统计仍待继续落实，详见 [迁移说明与需求差距](docs/MIGRATION.md)。

## 本机运行

打开 Docker Desktop，在本项目目录运行：

```powershell
./scripts/Start.ps1
```

访问 **http://127.0.0.1:8080**。前端已经装入 Java JAR，无需另外启动 Node 服务。

| 角色 | 账号 | 口令 |
|---|---|---|
| 管理员 | admin | admin123 |
| 模拟学生 | stu01 至 stu40 | 123456 |

数据库初始化包含3个模拟空间、158个座位、14天模拟历史。预约按校园时区当天至后两天、整分钟、至少30分钟校验；单段结束可为24:00，不设单次或每日4小时额度。候补和属性偏好自动分配已退出新增入口，历史记录保留。空间分段、日期例外与临时停用统一决定合法开放窗口。

扫码签到：管理员在“管理端 → 座位维护 → 座位码”填写理由生成并查看二维码，可轮换或启停。普通用户从“我的预约 → 扫码签到”上传真实二维码图片，或主动开启摄像头；只有本人预约、匹配且有效的当前座位码和合法签到时段才能签到。图片在本机识别；设备与实体打印的实际验证范围见F03实施方案。

使用与结束：签到后生成唯一使用记录，“我的预约”展示签到、结束、结算登记和使用时长。提前签退释放剩余时段；到期自动按原结束时间结算，不额外处罚漏点签退。不再提供暂离/返回操作，历史暂离依据保留，短暂离开不延长原结束。新记录不再增加信用奖励或扣分。

找座预约：选择日期和空间，比较最早可约、连续可用最久或满足所需学习时长三种方案，可切换平面图和逐段列表，3D沿用同一结果。空档已扣除座位占用、本人其他空间安排及停用限制；最早和最长方案默认预约30分钟，时长方案默认采用输入分钟，可在完整空档内主动修改。若本次短于找座输入，页面和确认框明确提醒。查询是快照，确认提交时再次校验，被抢后显示原因并刷新原条件。

资源变更：管理端编辑空间、座位、开放安排或临停时，先核对真实影响清单，再确认立即取消受影响预约；使用中还需登记管理员自报的协调依据，按确认时刻结算已用时长。取消预览保留表单，清单变化须重新预览。恢复资源不会复活原预约，本人可查看当次公开原因与使用记录；系统不据自报证明现场已经腾退。

求助投诉：普通用户可从“我的预约”关联本人预约发起座位被占求助，也可从“求助与投诉”独立提交一般服务问题。历史预约可留证，提交不延长签到期限或恢复预约；成功仅表示待受理。支持仅文字，或附最多三张PNG/JPEG材料，每张不超过5MiB；图片实际保存并鉴权读取，失败保留文字，可主动重试。未绑定临时材料24小时后失效并定期清理，已绑定材料保留。本人列表与详情可刷新核对。

管理核实：管理端“投诉管理”可受理并追加不可覆盖的核实记录，首受理人保持、每次操作者独立留痕。占座处置须管理员明确记录当时的事实、预约权利及所需身份依据；身份未知不猜测账号，一般服务问题可独立核实。配合纠正生成独立提醒，本人个人中心可查允许范围，提醒不计违规；公开进度与管理私有依据分开。核实记录属于管理员自报，不证明系统核验了真实现场。

违规登记：管理员可从已核实身份、事实和预约权利的拒不配合事件另行登记违规，独立填写向被登记者公开的事实说明；核实动作本身不自动处罚。同来源事件或完全相同的事实只登记一次，历史投诉不必重开。被登记者收到站内通知，可在个人中心查看类型、来源、事实、发生与登记时间、真实通知时间和登记人；涉及投诉人预约的编号不公开。旧记录没有可靠通知关联时明确显示未留存，不猜历史通知时刻。原自动未签到、主动放弃违规继续沿用同一记录与通知核心。

预约限制：管理端“预约限制”可核对普通用户账号，填写公开原因、明确截止和私有核实依据后登记立即生效的限制，也可有理由地解除其中一条。多条有效限制分别生效；解除一条不代表恢复预约资格。限制先落实原已到期预约事实，再取消仍有效的待签到预约且不因此记违规，已签到使用可继续到原结束；取消记录不复活。个人中心展示当前资格和本人限制，预约被拒绝时展示服务端原因。旧信用限制只接管剩余有效期并保留原截止，接管起点不冒充原处罚起点，旧分数和流水保留。系统每次核查按真实发生时刻回溯30×24小时，取三条有效且未用于旧自动批次的最早违规，生成7×24小时限制并保留三条来源；本人及管理端均可查看本批原窗口和依据。任何有效限制期间延后新批次，全部结束再核查仍在窗口的余留事件；解除最后一条可能立即形成新批次。已消费事件不因解除或到期重复处罚，旧分数不换算违规。申诉成立后按原固定来源重算原批，永久消费关系保留；当前资格仍可受其他限制或新积压批次影响。

本人申诉：从本人违规记录进入“查看申诉条件/进度”，按服务端保存的真实违规通知时间，在原7×24小时内提交说明和可选照片，个人中心可查进度，管理员在“申诉待办”查看原件。旧记录没有可靠通知时间时明确无法确认线上期限，不猜时间或补发重置；已有待审可直接查看。照片须本人新上传的申诉用途材料，不借此读取原投诉人的图片；与投诉共用完整校验和受控存储。提交仅表示待审核，不撤销违规、解除限制或恢复预约；管理员可先只读预览再确认同意或驳回，填写公开理由与私有核实依据；批准只撤销原违规并重算原批，不恢复已终止预约。本人可查看审核结果与当前资格，驳回后原通知窗内可补充新申请。

反馈结案：管理处理中可发出正式结果与公开依据，站内通知可进入本人详情。待受理可撤回；每次反馈起7×24小时内，本人可确认结案或提出异议回到处理中，再反馈重新起算，旧历史保留。到期无确认或异议则系统结案，区别于本人确认；查询、操作与任务共用到期规则，旧页面跨过截止也会得到真实失败反馈。状态和截止以服务端为准，写入结果不明时保留原操作ID主动重试。

处理目标：被占求助在空间开放时提交，从提交起15分钟接单开始核查，跨闭馆不暂停；非开放时提交从当时已知的下次空间开放起算。一般服务投诉从提交起24小时首次正式反馈，受理和核实不替代反馈。提交时冻结目标与依据，资源后续变更不自动顺延；未知下次开放、旧被占投诉缺少历史依据时如实显示待定。受理或首次反馈后停止相应目标，撤回只表示停止；超时是管理服务提示，不计用户违规。页面剩余时间为服务端快照的单调估算，到期自动核对一次，最终状态以服务端为准。

停止 Java：`./scripts/Stop.ps1`。该脚本不会关闭共享数据库或 Redis。

修改代码后：

```powershell
./scripts/Build.ps1
./scripts/Stop.ps1
./scripts/Start.ps1
```

Java 从 `.local/server.jar` 独立副本运行，不锁定 Maven 构建产物。日志在 `.local/server.log` 与 `.local/server-error.log`。

数据库结构由 Flyway 增量迁移管理。旧版无迁移历史的数据库首次升级默认拒绝启动；停服务并备份后，通过应用参数 `--studyroom.migration.adopt-legacy=true` 一次接管，程序核对结构与V1一致后才升级，完成后移除参数。未知结构不能盲目baseline；恢复与验证见 [F01架构方案](docs/features/F01-校园账号与权限/校园账号与权限功能架构方案.md)。

首次部署或换一台电脑时：

```powershell
./scripts/SetupPostgres.ps1
```

脚本生成随机口令、同步应用配置、创建容器和持久化卷，首次自动创建开发库和测试库。重复运行不会清空数据或轮换口令。不要删除数据卷来修复普通启动问题；已有卷不会因修改 env 文件而自动修改数据库口令。

本机 Redis 复用 `my-redis` 的6379端口，使用3号库和 `studyroom-java:` 键前缀。可选 `docker compose --profile extra-redis up -d redis` 会另建6380实例，使用时需同步修改应用配置。默认启动不会创建重复 Redis。

## 开发与验证

需要 JDK 17、Maven 3.6+、Node 24+、Docker Desktop。前端二维码解码依赖要求Node24，本机实际为24.14.0。本机已配置 IDEA Maven 路径；换电脑可设置 `$env:STUDYROOM_MAVEN='你的mvn.cmd路径'`，或在 IDEA 打开 `backend/pom.xml`。

前端热更新：在 `frontend/` 运行 `npm ci`、`npm run dev`；默认5173代理到 Java 8080。

```powershell
./scripts/Build.ps1 -Integration
```

集成测试只使用并清理专用测试库 `studyroom_java_test`，代码会检查库名。普通构建可省略 `-Integration`。需要额外HTTP联调时，先在8081启动明确连接测试库且已有模拟种子的独立服务，再执行 `python ./scripts/api_smoke.py`；脚本默认8081，并在任何业务写入前核对健康响应的实际库名，只允许 `studyroom_java_test`。可通过 `STUDYROOM_API` 指定专用测试服务地址，但不能指向开发库；模拟预约最终取消，临时无历史房间会删除。

[本次验证结果](docs/VALIDATION.md) 与上游资料分开保存。`docs/upstream/` 和 `diagrams/` 是原作者材料，不等于本组贡献或本次测试结果。

后端入口为 `backend/src/main/java/cn/studyroom/`：`Requests` 定义前端契约，控制器提供接口，`AuthService`/`WebSecurity` 负责权限，`UserService` 维护校园账号，`ResourceService` 管理资源，`OpeningScheduleService` 计算合法窗口，`ResourceChangeService` 编排预览与管理取消，`Slot`/`BookingService` 统一预约时间与事务，`UsageService` 记录实际使用，`RestrictionPolicy` 维护限制事实与资格、`RestrictionWorkflow` 编排限制及既有预约善后，`AvailabilityService` 计算连续空档，`StatsService` 汇总统计，`Store` 处理 SQL 和保真时间映射。

应用仅监听127.0.0.1。上游来源和许可证在本项目中保留；原作者材料不能作为本组的实现或测试结果。


核实补签：管理端“核实补签”按真实预约编号查询，填写业务签到时刻、公开理由及私有核实依据，明确自报后确认。仅原签到期限内仍有效、账号与资源可用且无冲突的待签到预约允许操作；截止、已终止或已有使用记录不能补签恢复。本人使用记录展示补签来源、业务时刻与真实操作时刻，可沿原流程签退；私有依据仅管理员可见。


本人使用评价：在“我的预约”打开“评价/查看本人评价”，由服务端核对本人真实签到及已结束使用，支持1—5整数星和文字，每预约一条、本人可修改。管理资源提前终止但实际使用已结算也可评价；未签到取消及未结束使用不能评价。原创建时间保留，修改按版本防覆盖，提交失败保草稿；管理回复和隐藏结果可从本人评价查看；已隐藏评价本人可修改，但修改不恢复公开。


评价管理与公开：管理端“评价管理”支持按空间与公开状态筛选、回复或有理由隐藏，不修改用户评分原文。本人收到站内通知，可跳转查看真实结果、回复及隐藏理由。所有登录角色可在“空间评价”按空间查看公开匿名内容与管理回复，服务端排除隐藏项及身份/预约字段；请勿在评价文字中自行填写个人信息。隐藏保原文、评分及历史，未提供删除或自动恢复公开。

记录查询：本人预约、违规、限制、投诉及申诉均可按各自日期和状态筛选并使用服务端分页，总数由完整查询计算。预约另按空间、座位编号和真实使用范围查询，停用空间的历史仍可定位。管理端提供“预约与使用记录”“违规记录”及原领域查询；管理限制的私有核实依据从独立管理详情读取。页面显示最后成功读取时刻及对应条件，读取失败保留该快照；通知关联的本人违规、限制可独立定位到当前页之外的记录。

消息中心：按消息类型和已读状态服务端筛选分页，完整本人汇总与筛选总数分开显示。单条及全部已读展示实际标记数并复核权威未读数量；重复标记不会再次计数，新消息仍会显示未读。新业务通知带可靠关联，可打开本人真实预约、违规、限制、投诉、申诉或评价；未保存关联的历史消息保留原文并说明无法定位，不根据正文猜目标。角标读取失败保留成功值并可重试。

审计查询：管理端可按校园日期、操作者、对象及动作精确筛选已有审计，分页查看公开操作理由与必要变更。详情为有界安全投影，明确列出省略、脱敏与截断数量，私有核实原件须到所属领域管理详情核查；不提供审计编辑或删除入口，读取保持原业务事实。
